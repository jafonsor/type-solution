**Decisions the plan did not settle (to confirm)**
1. The status line's exact wording: `doesn't type-check yet: line 4, column 5: <message>` (verdict, then position, then the cleaned message; cut with an ellipsis when long, the hover holds everything). The plan gives the verdicts and says "line and column".
2. The cleaned message is puzzle-check's: the compiler's whole body up to the `See https://` link, 300 characters, so a type error carries its "while checking that ..." lines.
3. The syntax underline: when the reported position has text before it on its own line, it is the token itself (the rule "end of the last non-blank line" is applied to a position at the start of a line, which is what the plan describes: "the line after the break"). A literal reading would put it on the line before even then.
4. The loading line takes the status line over while the shown Language is loading or failed and the Run is not Paused, Skipped or Passed; a Passed Run keeps its pass line.
5. The checkbox is a native checkbox in a `label` in the menu (so it is only on screen when the menu is open); the underlines option applies to both Languages.
6. A compile error is no longer repeated in the feedback line under the status (JavaScript's `Syntax error: ...` line is gone; its text is the status line and the hover).
7. The sibling scripts `purs-compiler.js` and `purs-sandbox.js` are found by plain name next to the hashed `runner.js`; on Pages the plain name is cached for `max-age=600`, so for up to ten minutes after a deploy the old worker script can meet the new page.
8. JavaScript's `column` moved from 0-based to 1-based (internal Checker contract; no other consumer).
