## Comments

**What was built.** `tools/purs-bundle/build.mjs` (Node; drives the compiler through `tools/puzzle-check/purs-runner.js`, which now exports `openSession`, `runCompiler`, `stripAnsi`) and the Nix derivation `purs-bundle.nix` (flake output `.#purs-bundle`, takes `purs-core-wasm`; library sources fetched at their commits with `languages/purescript/source-hashes.json`, regenerated by `tools/purs-bundle/prefetch-hashes.mjs`). Output: the compiler, 40 library packs, `names.<hash>.json` (data for ticket 32, no popup), `manifest.<hash>.json`, and the pointer `current.json`. All named with a 16-digit content hash except the pointer. The app side is Language-agnostic and lives in `static/bundle/` (`pack.mjs`, `bundle.mjs`, `trigger.mjs`, plus `purs-tree.mjs` which is PureScript's tree builder). It is outside `static/editor/` on purpose: any change there changes the default derivation. Ticket 31/29 wires it in (a Language value gets `bundle: {...}`; move or import the modules into the editor bundle then).

**Acceptance, how proven.**
- Download only on first pick / remembered at load: `static/bundle/test/trigger.test.mjs` (7 tests: the rule, JavaScript-only use starts nothing, shared in-flight download, retry after failure) and, in real Chrome 157 and Firefox 158, `tools/purs-bundle/browser/drive.mjs` / `drive-firefox.mjs`: `javascriptOnly_bundleRequests: []` after page load and a JavaScript pick; the first PureScript pick requested exactly `current.json`, the manifest, the compiler and the name table; a reload with PureScript remembered requested only `current.json`.
- Hashed names and manifest, per-library fetch, Cache Storage: `tools/purs-bundle/test/build.test.mjs` (hash in every name equals the file's sha256; manifest lists exactly the pinned libraries; a pack holds only its library; two builds are byte-identical; a tree from only the needed packs compiles with only `Main` rebuilt) and `static/bundle/test/bundle.test.mjs` (pointer revalidated, no library fetched on open, pack fetched once with its requirements, second visit makes only the pointer request, a new version deletes the old files but keeps the unchanged compiler, offline fallback, progress). In Chrome the new-version case left only the new manifest's files in Cache Storage.
- Figures: in the spec, "Measured in ticket 28".

**Findings the plan did not have.**
- `arrays` requires 28 libraries, so `import Data.Array` loads 29 (567 KB gzip, 6.1 MB tree) and the check is 0.56 s warm in Chrome (0.37 s in Firefox) against 0.18 to 0.23 s for Prelude only; with every source given to the compiler it is about 40% slower. The 400 ms target is at risk for Solutions that import `arrays`; the Checker worker (31) should pass only reachable sources (`sourcesFor`) and re-measure on a quiet machine.
- The compiler rebuilds libraries unless every file from a pack reports the same modified time (`sourceMtime` in the manifest). Recorded in the spec and `purs-tree.mjs`.
- GitHub Pages serves gzip, never brotli, with `max-age=600`: the compiler downloads as about 3.5 MB, not 2.3 MB.
- The pointer `current.json` is the one file without a hash (needed to find the manifest without touching the app's build); it is fetched with `cache: "no-cache"`.
