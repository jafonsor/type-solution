# 30: Saved data, Personal bests, weak-key lists, `peeked` flag per Language, and the `?` Reference Solution tooltip

## What to build

Build order step 4, second part: the `language` field on runs (missing = JavaScript), keys, Personal best per Puzzle and Language, weak-key lists per Language, the `peeked` flag (ticket 15 and 16 decisions).

Scope widened by the owner (decision outside the plan, 2026-11-10): this ticket also builds the `?` hoverable Reference Solution tooltip in the thin bar under the editor (ADR 0001, spec "Choosing a Language"), showing the current Language's Reference Solution from the Puzzle's per-Language table (`Common.Puzzle.languageTable`), and the peek mark: the tooltip open for about 1 s or more, in any Language, marks the whole Run "peeked" (spec "Peeking"). Without it the `peeked` flag could never be set. Also settled: while a Run is Paused (menu open) the editor is read-only, the Language dropdown stays disabled and Alt+L does nothing (ticket 29's behaviour stands).

- [x] The `?` tooltip shows the current Language's Reference Solution on hover.
- [x] The tooltip open for about 1 s or more, in any Language, marks the whole Run peeked; the record carries `peeked`, and the plain word "peeked" shows with the time (end-of-Run result, beside the best on the status line).

**L3, ticket 29's note (3): it did violate L3, and is fixed here.** Switching stopped the check in flight for the Language left, and the single 400 ms debounce kept only the latest edit of whichever Language, then dropped it if the Language had changed. So a draft that was complete when the player switched was never checked until they came back; the other Language could pass first and end the Run although the first draft would have passed earlier. Now: each Language has its own debounce (built from the registry's list); a check begins 400 ms after its Language's last edit whichever Language is shown, if it is still that Language's draft in the Run (`draftOf`, so a new Run or later typing makes an older one stale); switching stops nothing; a new Run stops every Language's check. `Run` awaits one check per Language: a pass of any ends the Run in that Language; a failure of a Language that is no longer shown is ignored (it says nothing about the draft in front of the player, and the shown outcome is cleared on a switch anyway). Tests: "a check in flight for the Language left still ends the Run when it passes, with that Language's Solution", "a check that begins after the switch, of the Language left, counts too", "the other Language passing first ends the Run in that Language; the later one is ignored", "a failure of the Language left tells nothing about the shown draft", "an edit drops only the check of the Language edited", "switching back to a Language whose check is still in flight shows its outcome when it arrives".

Decisions the plan left open, made so the feature works (to be confirmed):
1. A peek before the first keystroke, and during a Pause, counts for the Run that follows or is under way (the likeliest peek is before typing; a Run only starts at the first key). After a skip or a pass it does not.
2. The wording: `12.3 s (peeked)` beside a Run's own time and a best, `New best (was 14.0 s, peeked)` inside the parentheses. The ticket says only "the plain word peeked". The live clock does not carry it, and there is no list of bests in the app yet.
3. A record's key presses are kept whole (all Languages) with `keyLanguages` stretches. A Run is in a Language's window of 20 when it has presses typed in that Language; for a Run that never switched this is exactly "that Language's records", but a switched Run also counts in the Language it left, which the plan's sentence taken alone does not say. The first press of each stretch typed in a Language is not a Hesitation (its gap includes the switch).
4. The tooltip reacts to the mouse only (no keyboard focus, no touch), as the plan says hover.
