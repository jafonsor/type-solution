## Comments

- `src/import-popup.mjs` (Language-agnostic): turns a Language's `importRules` seam (`{names, isImportLine, offers, importEdit}`, documented in `src/languages.mjs`) into the popup: 2 letters, up to 6 offers each with its module, never on an import line, `apply` dispatching only the import edit tagged `userEvent: "input.complete"` and then `closeCompletion`, a highest-precedence Tab binding that runs `acceptCompletion` (false with no popup, so `indentWithTab` indents), `activateOnTypingDelay: 0`, `interactionDelay: 0`, no `validFor`, `filter: false` (the Language's own order). Decisions the plan did not settle, taken to make it work and to be confirmed (listed in the report to the owner): (1) Esc with the popup open closes only the popup; (2) a name two modules export is offered once per module, preferred first (the alternative is the preferred module only); (3) alphabetical order, so `ta` offers `tail` first; (4) names Prelude exports are never offered, and neither are the names of a module imported whole; (5) the table lists types but no constructors, so `Maybe` is offered as `Maybe` (not `Maybe(..)`) and `Just` is not offered; (6) an indent rule after `where`, `do`, `of`, `=`, `->` and friends; (7) a class is imported as `class Name`. For ticket 31: `bundle.core("names")` opens the bundle, which fetches every core file (the 23.5 MB compiler) before it returns, so the popup would wait for the compiler on the first PureScript pick; if that is slow, the loader needs a way to fetch the name table alone.
